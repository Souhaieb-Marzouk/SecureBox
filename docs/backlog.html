How this file is maintained

  1. New feature → add to ITEMS with type:"feature", a priority, an area and a milestone. Give it the next free SB-xxx id.
  2. Feature shipped → either delete the entry (once released) or set status:"done" and doneAt so it appears under Done for one release, then remove it.
  3. New issue faced → add with type:"issue", the symptom, the workaround (if any) and what “fixed” means.
  4. Issue fixed → set status:"done" + doneAt and reference the commit in the description. Never leave a fixed issue in the open list.
  5. Every release → re-rank P0–P3, update LAST_UPDATED, and add a row to the update log below.

Priority meaning — P0: blocks a release or is a security/privacy risk; P1: must land in the next release; P2: planned next milestones or significant UX debt; P3: later milestones, polish and process.
