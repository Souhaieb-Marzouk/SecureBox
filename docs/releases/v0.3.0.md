# v0.3.0 — App Security Scanner

SecureBox can now audit every app on the device: permissions, trackers, components, installer source and suspicious code signatures — entirely on-device, with a plain-language risk score.

## 🎯 Highlights

- **One-tap on-device scan** of every installed app: signature rules, tracking SDKs, dangerous permission combinations, exported components, accessibility services, device admins and hidden launcher icons.
- **A risk score with reasons** — every app gets 0–100 and a list of plain-language findings such as "reads SMS and can control the screen".
- **Sideload awareness** — apps installed outside the Play Store are badged and explained, which matters most on cheap TV boxes.
- **Automatic protection** — weekly scans plus a scan after boot (both optional), with a notification when risky apps are found.
- **Daily update check** — SecureBox now checks for updates in the background and notifies you when a new version is available.
- **Permissions stay accurate** — usage access, notifications and VPN consent are re-read every time the app returns to the foreground.

## 🛠️ Technical Changes

- New `core-domain/security` layer: `RuleEngine` (YARA-style substring rules), `PermissionAuditor` (dangerous permission combos), `RiskScorer` and `SecurityRepository`, covered by 15 new unit tests (41 total).
- `core-data`: `AndroidSecurityRepository` audits packages, installer source, components and devices admins, and deep-scans user apps by extracting printable strings from their DEX files (`DexStringExtractor`).
- Scanner rules ship as an AES-256-GCM encrypted asset. The key is a build-config constant, so this is obfuscation, not a secret; the readable source lives in `docs/scanner-rules.json` and the design leaves room for the Ed25519-signed feed in v0.5.0.
- `feature-apps`: real app list with risk badges, All / Risky / Sideloaded filters and a detail dialog explaining each finding.
- `feature-threats`: scan card with progress, summary, risky-app list and the weekly-scan toggle.
- `app`: `ScanWorker` (weekly), `BootReceiver` (post-boot one-off), `UpdateCheckWorker` (daily), scan/update notifications and permission refresh on resume.
- Version bumped to `0.3.0` (`versionCode 4`); new permission `RECEIVE_BOOT_COMPLETED`.

## 🐞 Fixes

- Permission state is no longer stale after changing system settings; it refreshes on every resume.
- Update availability now reaches the user even if they never open Settings.
- `v0.1.0`/`v0.2.0` release titles already use the specified em dash; `v0.2.1` staging was superseded by this release.

## 🔐 Security Notes

- Scanning is **local only**. APK bytes, app names and findings never leave the device.
- Deep scanning covers user-installed apps; system apps are audited for permissions and components but their APKs are not read.
- The encrypted rules asset is tamper-resistant against casual edits, not against someone with the APK. Rule signing arrives with the v0.5.0 feed.
- No new dangerous permission; boot scanning only enqueues WorkManager work when the user left scheduled scans enabled.

## 🔄 Update Notes

- Installs directly over v0.2.x (same signing certificate); settings, blocked apps and anomaly history are preserved.
- The first scan runs on demand; weekly scans start after the app is opened once so WorkManager can be scheduled.
- Findings are heuristic. A "Medium" badge is a prompt to look, not proof of malice; the detail dialog explains every reason.
- On Android 10+ some component data is restricted by the platform; SecureBox shows what the OS exposes and does not guess.
