# v0.4.0 — Hardening & Platform Polish

This release adds the defensive layer around the scanner: tamper detection, a device-hardening checklist, adaptive layouts for tablets and TV, smoother phone interactions, and a native packet pump for the firewall.

## 🎯 Highlights

- **Device integrity checks** — SecureBox now looks for an attached debugger, an emulator, root indicators and a signature mismatch, and shows the result in Settings. A tampered build cannot install updates.
- **Device hardening checklist** — developer options, USB debugging, accessibility services, device administrators, user-installed certificates and install-unknown-apps are audited in one screen, each with a **Fix** shortcut to the right system setting.
- **Tablet and foldable layout** — the phone shell switches to a navigation rail on wider screens using `WindowSizeClass`; the TV sidebar now takes D-pad focus on launch.
- **Better phone ergonomics** — pull to refresh the app list, and tap an app for a bottom-sheet explanation of its rating.
- **Native packet pump** — the firewall's packet discard loop now runs in C/C++ over JNI, with the Kotlin reader kept as a fallback for unsupported ABIs.

## 🛠️ Technical Changes

- New `IntegrityRepository` (debugger, emulator, root, signature) and `DeviceSettingsRepository` (system settings audit); both wired through Hilt and surfaced in Settings/Threats.
- `UpdateViewModel` refuses to download when integrity is compromised (`UpdateFailure.INTEGRITY`).
- `HardeningScreen` lists settings with severity and opens the matching system screen.
- `PhoneShell` renders a `NavigationRail` at `WindowWidthSizeClass.Medium` and above; `TvScaffold` requests initial focus on the first sidebar entry.
- `PullToRefreshBox` implements pull-to-refresh with a nested-scroll connection, so list scrolling is untouched.
- App details use a `ModalBottomSheet`.
- Native `securebox_pump` built with CMake against NDK 27.2.12479018; JNI `drain(fd)` reads and discards TUN packets, Kotlin fallback retained.
- Instrumented Compose tests for the Apps and Threats screens; CI matrix runs them on a phone (API 34) and Android TV (API 33) emulator.
- Version `0.4.0` (`versionCode 5`).

## 🐞 Fixes

- TV sidebar had no deterministic initial focus.
- App list required a manual Refresh button (pull-to-refresh now works).
- App details on phones used a dialog rather than a bottom sheet.

## 🔐 Security Notes

- RASP is heuristic: root/emulator detection can be bypassed by a determined attacker. It raises the cost and gives honest users a clear signal, but it is not a guarantee.
- The hardening screen only reads settings; it never changes them silently. Each Fix opens the system UI where the user makes the change.
- The native pump still discards packets locally; no traffic is forwarded, and no new permission is requested.
- A tampered build cannot self-update, which prevents an attacker who re-signs the APK from pushing further updates through it.
