# v0.5.1 — Threat Intelligence & Polish

This release adds the signed threat feed, closes the update and i18n polish items, and ships an x86_64 build. It also documents the one architectural limit found while implementing the feed.

## 🎯 Highlights

- **Signed threat feed** — a versioned `latest.json` is verified with an embedded Ed25519 public key before anything is stored. A missing, malformed or tampered signature rejects the whole feed.
- **Threat Intelligence screen** — feed version, rule/tracker/domain counts, installed and last-checked dates, signature status, **Update now**, and a daily auto-update switch.
- **Feed adds detection without an app update** — verified rules are merged into the scanner and tracker prefixes into the SDK detector. A feed with a higher version updates the ruleset atomically.
- **Signed release manifests** — every release now includes `SHA256SUMS.sig` (Ed25519), with `tools/verify-release.mjs` for offline verification.
- **x86_64 APK** — `securebox-x86_64-release.apk` is produced and preferred by the updater on x86_64 emulators.
- **Polish** — clickable links and fenced code blocks in release notes, stale APKs cleaned from `cacheDir/updates`, a local-only paid-tier placeholder, and the French review closed.
- **Performance** — cold start measured at **400–414 ms** on the reference OPPO phone; universal APK **2.29 MB** (budget 40 MB).

## 🩹 Audit fixes (0.5.1)

- **IPv6 firewall bypass fixed** — the tunnel now captures IPv6 as well as IPv4, so a blocked app can no longer reach the network over IPv6.
- **Update installer fixed on debug builds** — the FileProvider authority is derived from the runtime package name instead of a hardcoded release value.
- **Feed hardening** — downloads are capped at 2 MB, zero-version/empty feeds are rejected, the service keeps a single state collector, and tunnel rebuilds are serialized.
- **Background work** — daily update and feed workers now require network connectivity.
- **Backup** — explicit no-backup `dataExtractionRules` and `fullBackupContent`; `allowBackup=false` retained.
- **Icons and i18n** — monochrome launcher icon, French `many` plurals, plural notification strings, missing banner densities, unused colours removed.
- **Dashboard** — the firewall factor now counts only when the tunnel is actually running, not when consent was merely granted.
- **CI** — release workflow now includes the x86_64 APK, verifies the signed feed, and optionally signs `SHA256SUMS`; `.gitattributes` pins the feed bytes to LF so signatures survive Windows checkouts.
- **Docs** — BUILDING lists NDK/CMake, SECURITY lists supported versions, TESTING is version-independent.

## 🛠️ Technical Changes

- New domain contracts `ThreatFeed`, `ThreatFeedStatus`, `FeedUpdateResult`, `ThreatFeedRepository`.
- `ThreatFeedRepositoryImpl` fetches `latest.json` + `latest.json.sig`, verifies with `net.i2p.crypto:eddsa`, parses rules/trackers/domains and stores them atomically in DataStore.
- `AndroidSecurityRepository` merges verified feed rules and trackers into the bundled ruleset; `rulesVersion()` reports the higher version.
- `feature-threatintel` screen + view model, opened from Settings; daily `ThreatFeedWorker` honours both the module toggle and auto-update preference.
- Starter feed at `threat-intel/latest.json`, signed by `tools/sign-release.mjs`; `.github/workflows/threat-feed.yml` re-signs on change using the `THREAT_FEED_KEY` secret.
- `tools/verify-release.mjs` + `docs/RELEASE_SIGNING.md`; `docs/THREAT_FEED.md` documents the contract and key rotation.
- R8 keep rules for EdDSA; four ABIs in the release.
- 3 new Ed25519 tests (44 total); markdown link/code-fence rendering; update cache cleanup; paid-tier flag.

## 🐞 Fixes

- Older update packages are deleted before a new download and after verification.
- Release notes no longer print `[label](url)` and triple-backtick blocks as plain text.

## 🔐 Security Notes

- **The feed's `domains` list is stored and displayed but not enforced by the firewall.** The current VPN routes only blocked apps into the tunnel and discards their packets, so there is no DNS layer to filter domains on. Enforcing domains requires a separate forwarding-DNS design; SB-041 is tracked as blocked rather than silently claimed.
- The feed private key is offline (`_securebox_keys/threat-feed-ed25519.pem`); CI signs through the `THREAT_FEED_KEY` secret.
- Only the signed ruleset is downloaded. No app names, scans or device data are uploaded.
- A feed update never activates before signature verification and is written in a single DataStore edit.
