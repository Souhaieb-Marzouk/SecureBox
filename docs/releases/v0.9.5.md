# v0.9.5 — Combined firewall + DNS is working

v0.9.4 proved the forwarding path end-to-end on a physical phone: DNS resolves, TCP handshakes complete, TLS payloads flow both ways, and both **DNS Protection** and **Local Firewall** can stay enabled together.

This build removes the temporary packet dumps and fixes the small RST/map issue they exposed.

## What the log confirmed

- **272 TCP SYNs**, **238 connected**, **208 remote payloads** — the relay works.
- No `tun write failed`, no `tun reader stopped`.
- DNS replies are real (typically 16 bytes larger than the query for a single A answer).
- The only repeated failures were `192.168.8.1:7` — an external device/app probing the router’s echo port, not SecureBox.
- `protect()` returns `false` on this phone; the underlying-network fallback is what makes TCP work there.

## Verified on physical phone (2026-11-09)

- Local firewall and DNS Shield enabled **together** — internet works.
- A selected blocked app has **no internet**.
- A non-blocked app still works.
- An ad/tracker test domain is blocked by DNS Shield.
- Protection statistics increment the DNS block counter.


## Changes

- Removed the temporary SYN-ACK hex dump.
- Removed per-packet TCP flag/sequence logging.
- Removed remote-payload logging.
- Rate-limited `protect returned false` to one line.
- Unsolicited TCP RSTs no longer create throwaway flow objects.

## Known limits

- The tunnel is **IPv4-only** in this build. IPv6 traffic is not filtered; it is not routed into the VPN.
- Per-app blocking depends on UID attribution; if the phone refuses the UID, the flow is allowed.
- Apps using their own DoH/DoT resolver can bypass DNS filtering.
- HTTPS is not intercepted.
- YouTube in-stream ads are not removed.
