# v0.9.3 — Protect fallback

The v0.9.2 log showed the remaining blocker precisely:

```text
tcp connect failed :443
java.lang.IllegalStateException: protect failed
```

`VpnService.protect()` returned `false` for every outbound TCP socket, so the engine aborted before `connect()`. DNS worked because its path did not hit that abort.

On some Android builds the VPN app’s own traffic is already outside the tunnel, and `protect()` can return `false` for a perfectly usable socket. Refusing the connection was wrong.

## Fix

- If `protect()` returns `false`, SecureBox now:
  1. logs it,
  2. binds the socket to a non-VPN network with `ConnectivityManager.bindSocket()`,
  3. continues with `connect()` instead of aborting.
- The same fallback is used for UDP and the DNS fallback.
- The DoH socket factory no longer throws when `protect()` returns `false`.

This should let the TCP proxy open upstream connections. The next log will show either `tcp connected` or the actual exception from `connect()`.

## Test

1. Install v0.9.3.
2. Enable **Local firewall** and **DNS Shield**.
3. Try `https://1.1.1.1` and a normal HTTPS site.

Expected log:

```text
protect returned false; binding underlying network
tcp connected :443
```

If it still fails:

- `underlying bind failed` means no non-VPN network was found.
- `tcp connect failed` now includes the real exception after the binding attempt.

## What did not change

- IPv4-only tunnel
- combined firewall + DNS in one VPN
- DoH with protected plaintext fallback
- `SecureBoxTunnel` diagnostics
- stats and TV focus work
