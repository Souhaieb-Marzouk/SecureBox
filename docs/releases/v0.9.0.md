# v0.9.0 — Combined Firewall + DNS

One VPN now forwards allowed apps, blocks selected apps by UID, and filters DNS at the same time. Local firewall and DNS protection can finally be enabled together — including on TV boxes without Private DNS.

> **This is a new forwarding engine and needs physical-device testing.** v0.8.0 remains available if the engine misbehaves on your box. The privacy model has changed: allowed app traffic is now relayed on-device by SecureBox.

## 🧠 What changed

Previous versions had two mutually exclusive data planes:

- Local firewall: only blocked apps entered the tunnel and everything was discarded.
- DNS Shield: only DNS resolver addresses entered the tunnel; other traffic bypassed it.

Android permits one VPN. v0.9.0 replaces both with **one all-app forwarding VPN**:

- All apps are inside the tunnel.
- Allowed apps' **TCP flows** are terminated by a local forwarding engine, connected through `VpnService.protect()` sockets, and relayed.
- Allowed apps' **UDP flows** are forwarded through protected datagram sockets, so QUIC still works.
- Apps selected in the Local firewall are matched by **UID**; their TCP SYN gets a reset and their UDP packets are dropped.
- DNS is intercepted on port 53, checked against the local ad/tracker list, and forwarded over **DoH** to AdGuard, Cloudflare for Families or Quad9.
- **Both switches can be on at once.** The service stays alive when either control is enabled and stops only when both are off.

## 🔐 Privacy meaning — read this

This is not the old “we never forward” model.

- **Allowed traffic is now relayed by SecureBox’s local sockets.** It goes directly from your device to the destination.
- It is **not sent to a SecureBox server**, **not stored**, and **TLS is not intercepted**.
- SecureBox is in the data path for allowed apps, like any local VPN firewall.
- Blocked apps’ traffic is reset or dropped.
- The ongoing notification says this explicitly.

If that trade-off is not acceptable, use v0.8.0 and keep the firewall and DNS modes separate.

## 📱 How to use

1. Install v0.9.0.
2. Accept the VPN prompt once.
3. Open **Network → Local firewall**, turn it on, and select the apps to block.
4. Open **Privacy shield → Set up DNS**, turn on **DNS Shield**.
5. Both stay active in the same tunnel.

The DNS provider is selected in the DNS screen. AdGuard is the default.

## ⚠️ Known limits

- **IPv4 TCP/UDP forwarding.** IPv6 is routed into the tunnel and dropped so it cannot bypass the firewall; apps normally fall back to IPv4, but IPv6-only destinations will not work.
- **UID attribution** uses `ConnectivityManager.getConnectionOwnerUid` on Android 10+. Older boxes fall back to `/proc/net`. If the UID cannot be resolved, the flow is allowed rather than breaking an unknown app.
- **Apps with their own DoH/DoT resolver** can bypass DNS filtering.
- **YouTube in-stream ads** still cannot be removed by DNS or an embedded browser.
- **HTTPS is not intercepted.** No root or MITM.
- This engine has **not been validated on a physical phone or TV box** here. Test it and report the device/Android version if something fails.
- If v0.9.0 breaks connectivity, disable the VPN from the notification or reinstall v0.8.0.
