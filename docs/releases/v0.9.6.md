# v0.9.6 — Signed feed domains in DNS filtering

The signed Threat Intelligence feed already delivered scanner rules and tracker prefixes. Its `domains` list was stored and displayed but not enforced. It is now part of the VPN DNS blocklist.

## Change

- Feed domains are normalized and matched exactly or as parent domains (`cdn.tracker.example` matches `tracker.example`).
- The VPN refreshes the active signed feed at startup and every 15 minutes, so a feed update can block a domain without rebuilding the APK.
- Existing built-in ad/tracker domains remain.
- DNS block statistics count feed-domain blocks like built-in blocks.

## Test

1. Install v0.9.6.
2. Enable Threat Intelligence, update the feed, then enable DNS Shield.
3. Query a feed domain (the starter feed includes `ads.example.com` and `tracker.example.net`).
4. Confirm the DNS block counter in **Protection statistics** increases.

## Verified on physical phone (2026-11-09)

- Feed v1 active with 2 domains; Local firewall and DNS Shield both on.
- `ads.example.com` and `tracker.example.net` returned `unknown host`.
- DNS block counter rose from 563 to 565.
- DNS statistics flush within about one second, so a single block is visible without waiting for a batch of ten.
- 55 unit tests, 0 failures.
