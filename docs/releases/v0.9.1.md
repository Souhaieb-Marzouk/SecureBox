# v0.9.1 — Tunnel diagnostics (beta)

A focused follow-up to v0.9.0 for the “no internet when the combined VPN is on” failure. This build makes the tunnel IPv4-only, adds a protected DNS fallback when DoH is unreachable, and logs enough at the packet level to identify the failing stage.

> This is a diagnostic beta, not a finished stable release. If the VPN still breaks connectivity, disable it from the notification and collect the logcat described below.

## What changed

- **IPv4-only tunnel.** v0.9.0 routed IPv6 into the tunnel and dropped it; that could blackhole app connections before IPv4 fallback. v0.9.1 removes the IPv6 address and route while the forwarder is validated.
- **Explicit DNS-server route** for `10.111.0.2`.
- **Protected plaintext DNS fallback** when DNS-over-HTTPS fails. The local blocklist and DoH are tried first; only a failed DoH request falls back to `1.1.1.1:53` through a `VpnService.protect()` socket. This is a diagnostic safety net, not the preferred path.
- **`SecureBoxTunnel` logs** for:
  - first tunnel packets and their IPs/protocol
  - TCP SYN, connect success/failure, connected port
  - DNS query and response lengths
  - tunnel read/write failures
- No change to the stats page or TV focus work.

## Why this helps

The previous failure showed the VPN was active but traffic was not reaching the internet. The possible stages are:

1. apps’ packets never enter the tunnel
2. TCP connections cannot be opened from the protected socket
3. TCP handshake/data packets are malformed
4. DNS cannot resolve
5. IPv6 is blackholed

v0.9.1 removes IPv6 as a variable, gives DNS a fallback, and logs stages 1, 2, 4 and 5.

## How to test and report

1. Install v0.9.1.
2. Connect the phone to a computer with ADB.
3. Clear and capture the relevant log:

```powershell
adb logcat -c
adb logcat -s SecureBoxTunnel:I AndroidRuntime:E > securebox-tunnel.txt
```

4. On the phone, enable **Local firewall** and **DNS Shield**.
5. Open a browser and try:
   - `https://1.1.1.1` (bypasses DNS)
   - a normal HTTPS site
   - a blocked app
6. Stop the log capture and send `securebox-tunnel.txt`.

The important lines are:

- `packet proto=...` — apps’ packets are arriving.
- `tcp syn :443` — a TCP connection was attempted.
- `tcp connect failed :443` — the protected upstream socket failed.
- `tcp connected :443` — the upstream socket succeeded; if the browser still fails, the problem is in the packet relay.
- `dns query ... response=...` — DNS responses are being built.
- `tun write failed` — packets cannot be written back to the tunnel.
- `tun reader stopped` — the tunnel read loop died.

## Privacy note

The plaintext DNS fallback sends the DNS query to Cloudflare `1.1.1.1` without DoH **only when DoH fails**. The local blocklist is applied before it. If DoH works, the fallback is never used. This is a deliberate diagnostic trade-off and will be removed once the forwarding path is validated.
