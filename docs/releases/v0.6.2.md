# v0.6.2 — Permission Truth

The Apps tab now reports what each app **currently holds**, not what it merely declares. Scores, levels, recommendations and source filters all follow the permissions that are actually granted.

## 🔐 Permissions the app really has

- The list shows **only currently granted permissions**.
- Runtime permissions are checked against the app's package, so revoking Camera or Location removes it immediately from the list.
- Special access is checked as a capability, not a manifest string:
  - Display over other apps and Usage access use AppOps.
  - Accessibility is included only while a service from that app is **enabled**.
  - Notification listener is included only while the app is an **enabled listener**.
  - Device admin is included only while the app is an **active admin**.
- Normal permissions the app holds (internet, network state, boot, etc.) are still listed, with sensitive ones first.
- The list shows the count of permissions currently held and no longer shows a requested permission that was never granted.

## 🔄 Automatic refresh

- Returning to the Apps tab from Android settings automatically re-audits every app.
- The top **Refresh** button and a **Refresh** button inside each app's detail do the same.
- The open detail sheet updates in place after a refresh; if the app was uninstalled, the sheet closes.
- Overlapping audits are suppressed, so navigating quickly cannot start duplicate scans.

## 📊 Score based only on permissions

- The score and Criticality level now use **only the permissions the app currently has**.
- Risk signals (trackers, exported components, signature rules) are still shown, but they are labelled **extra context** and never change the score.
- The score is strongest-permission + breadth + dangerous-combination penalties, so a single SMS or accessibility grant is High while an SMS + screen-control combination is Critical.

## 🧭 Clear recommendation for every app

Each row now shows a short recommendation, and the detail sheet shows a full card:

- **Don't touch this app** — built-in system software; removing or changing it can break calls, Wi-Fi, updates or the launcher. If the system offers Disable and you don't use it, disabling is safer.
- **Reduce its permissions** — sensitive access the app may not need.
- **Consider uninstalling** — high-risk permission set, especially for apps not installed from the Play Store.
- **No action needed** — no sensitive permissions currently granted.

SecureBox never changes or uninstalls another app directly; the action buttons open the exact system screens.

## 🏷️ Know where every app came from

Every row has a coloured source badge, the detail shows the source, and the filter row now supports:

- **Built-in** — preinstalled system apps.
- **Play Store** — installer `com.android.vending`.
- **Other stores** — Amazon, Samsung, Huawei, Xiaomi, OPPO, vivo, F-Droid, Aurora, APKPure, Aptoide, APKMirror.
- **Manual (.apk)** — package-installer or unknown installer.
- **Unknown** — legacy/edge case from stored reports.

## 🛠️ Technical changes

- `AppSecurityInfo.permissions` now means currently granted permissions.
- Added `InstallSource.OTHER_STORE`, `AppRecommendation`, and `AppRiskReport.recommendation`.
- New effective-permission reader: `PackageManager.checkPermission` plus AppOps, AccessibilityManager, NotificationManagerCompat and DevicePolicyManager.
- `RiskScorer` now takes permissions; findings are report context only.
- Added source filters, source badges, recommendation cards, short row recommendations, and detail refresh.
- Permission changes are persisted in the report JSON for the latest scan.

## ✅ Verification

- **50 unit tests, 0 failures** (47 domain + 3 core-data).
- `verifyNoHardcodedStrings`, `lintDebug`, `assembleRelease` pass.
- Apps instrumentation APK compiles.
- A physical phone/TV smoke test was not possible here; if a permission's state looks wrong on your firmware, send the app name and the system settings state.
