# v0.4.1 — TV Layout Escape Fix

A hotfix for the one P0 found during device QA: switching a **phone** to "Android TV box" mode made the TV sidebar swallow the screen, leaving no usable content and no way back to the phone layout.

## 🎯 Highlights

- **The trap is gone.** On a narrow window the TV sidebar collapses to a 96dp icon rail and the content gets the rest of the screen, so Settings stays reachable.
- **Explicit escape.** When the TV shell is running on hardware that is not a TV, a **"Use phone layout"** button appears at the top of the content and switches back immediately.
- **Settings still works too.** Device mode → Phone remains the canonical switch; the escape is a safety net, not a replacement.
- No data is lost when switching modes in either direction.

## 🛠️ Technical Changes

- `TvScaffold` treats windows under 600dp as compact: 96dp icon rail, icon-only `TvNavItem`s, 12dp content padding instead of the TV 48dp.
- `TvNavItem` gained `showLabel`; labels are hidden only in compact mode and the icon keeps the label as its accessibility description.
- `TvShell` detects real TV hardware (`FEATURE_LEANBACK` / `FEATURE_TELEVISION` / `UiModeManager`), shows the escape button elsewhere, and `MainViewModel.usePhoneLayout()` persists `DeviceMode.PHONE`.
- Version `0.4.1` (`versionCode 6`).

## 🐞 Fixes

- SB-061: selecting TV mode on a phone no longer produces an unusable layout or a one-way trap.

## 🔐 Security Notes

No permission, network or scanning changes. This release only changes layout and the device-mode escape.
