# v0.1.0 — Foundation & Update System

The first public build of **SecureBox**, a privacy-first security app for Android phones, tablets and Android TV boxes. This release establishes the foundation: a clean multi-module architecture, a bilingual first-run experience, two genuinely different UI shells, and a complete, verified self-update pipeline.

## 🎯 Highlights

- **Bilingual onboarding (English / Français)** with automatic phone-vs-TV detection and a manual override that is remembered for every future launch.
- **Two real shells, one codebase** — a touch-first phone UI with bottom navigation, and a 10-foot TV UI with a sidebar, large focus rings and 18sp+ body text.
- **Self-update from GitHub Releases** — semantic version check, 12-hour cache, SHA-256 verification against the published `SHA256SUMS`, and a standard installer hand-off. A checksum mismatch deletes the file and tells you why.
- **A Security Score you can understand** — 0–100 with a documented, weighted breakdown instead of an unexplained number.
- **Zero telemetry.** The only outbound requests are the update check and (from v0.5) the optional signed threat feed.

## 🛠️ Technical Changes

- Gradle multi-module project (`app`, `core-domain`, `core-data`, `core-network`, `core-ui`, `core-tv-ui`, nine feature modules) with a single version catalog.
- Kotlin 2.0, Jetpack Compose, Compose for TV, Hilt, Coroutines/Flow, DataStore, OkHttp + Kotlinx Serialization, Navigation Compose.
- Clean Architecture boundaries: pure JVM domain, data/network implementations behind interfaces, Hilt at the application graph.
- Custom design system: navy/teal/amber/red palette (WCAG AA), 16dp rounded cards, a hand-drawn 24dp line-icon set, and inline "What is this?" explainers.
- `verifyNoHardcodedStrings` Gradle task plus `HardcodedText` as a lint error; both run in CI.
- GitHub Actions: CI on every push/PR, and a tag-driven release workflow that builds universal + per-ABI APKs, signs them from encrypted secrets, computes SHA-256, verifies the signature with `apksigner`, and publishes a GitHub Release with the notes and hashes.

## 🔐 Security Notes

- APK self-integrity check: the signing certificate SHA-256 is baked in at build time and verified at startup. A re-signed copy shows a warning banner.
- `allowBackup=false`, `usesCleartextTraffic=false`, FileProvider scoped to `cacheDir/updates` only.
- No Accessibility Service, no Device Admin, no SMS/call-log/contacts permissions.
- No signing key, token or secret is present in the repository; CI reads them from encrypted GitHub Actions secrets.
- Update installation is never silent; Android's installer always asks.

## 🧾 APK Assets

The workflow attaches `securebox-universal-release.apk`, `securebox-arm64-v8a-release.apk`, `securebox-armeabi-v7a-release.apk`, and `SHA256SUMS`. The exact hashes are appended to the bottom of this description at release time and are always available in the `SHA256SUMS` asset.

Verify a download with:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

## 🔄 Update Notes

- This is the first release, so there is nothing to upgrade from. Future versions will update in place through Settings → Check for updates.
- The update system requires `REQUEST_INSTALL_PACKAGES`; if you deny it, you can still install releases manually from GitHub.
- Because the app verifies its own signing certificate, **only builds signed with the official key can update an existing installation**. Debug builds use a different package id (`io.securebox.debug`) and coexist with the release app.
