# v0.2.0 — Network Intelligence & Local Firewall

SecureBox becomes an actual network security tool: see what every app transfers, catch upload spikes, cut an app off the internet locally, and inspect listening ports — still with zero telemetry and no traffic leaving the device.

## 🎯 Highlights

- **Per-app bandwidth, live and historical** — live rates refreshed every two seconds, plus 24-hour, 7-day and 30-day totals from Android's own statistics, sorted by consumption with a block switch on every row.
- **Upload anomaly detector** — learns each app's hourly baseline over 7 days and alerts when an app exceeds 3× that baseline or uploads more than 100 MB in an hour. Notifications offer **Block internet** and **Uninstall** actions.
- **Local-only firewall** — block any app's internet access with a `VpnService`, two presets (**Allow all** and **Block unknown apps** for sideloaded TV boxes), a persistent notification that states plainly that traffic is inspected on-device, and detection of another active VPN.
- **Open port monitor** — lists TCP/UDP listeners and attributes them to apps, flagging internet-facing sockets that could indicate a backdoor. When Android blocks `/proc/net`, the UI says so instead of pretending the device is clean.
- **Honest numbers** — the Security Score now reflects whether an update is actually available, and Threat Intelligence is clearly marked as not active until v0.5.0.

## 🛠️ Technical Changes

- New `core-domain` network layer: `AppTraffic`, `FirewallState`, `ListeningPort`, `AnomalyEvent`, repository interfaces and `DetectAnomaliesUseCase` (pure, unit-tested).
- `core-data` implementations: `AndroidTrafficRepository` (TrafficStats + NetworkStatsManager, graceful permission degradation), `AndroidPortRepository` (`/proc/net` parser with UID attribution), `FirewallRepositoryImpl` + `SecureBoxVpnService`, `AnomalyRepositoryImpl` (DataStore JSON snapshot) and a shared `AppRegistry`.
- Firewall model: blocked apps are the only applications routed into the tunnel, and every packet they send is discarded. There is **no forwarding**, so nothing can leave through SecureBox. If no app is blocked or none of the selected apps can be added, the service stops rather than capturing the whole device.
- `app`: hourly `AnomalyCheckWorker` (WorkManager), notification actions receiver, `QUERY_ALL_PACKAGES` for UID attribution, and the new foreground VPN service declaration.
- `feature-network`: complete phone + TV screen with app icons, range chips, firewall card, ports and anomaly sections.
- Version bumped to `0.2.0` (`versionCode 2`).
- 6 new unit tests for the anomaly rules; all existing tests still pass.

## 🐞 Fixes

- Security Score no longer assumes the installed build is current (previous release always awarded the 30-point update factor).
- Threat Intelligence is no longer presented as an active protection: the toggle is disabled and the copy says it arrives in v0.5.0.
- The keystore password is no longer stored in plaintext: `signing.properties` and `credentials.txt` were removed, the password is DPAPI-encrypted, and `tools/build-release.ps1` exports it only into the Gradle process.

## 🔐 Security Notes

- The VPN is **local-only**. SecureBox never forwards packets and never contacts a server for network features.
- The persistent notification states: "SecureBox inspects traffic locally on your device. Nothing is sent to us."
- Firewall is **off by default**; enabling it requires the system VPN consent dialog, and the app detects a conflicting VPN.
- Anomaly checks and scan results stay on the device; the only outbound calls remain the GitHub update check and the optional future signed feed.
- `QUERY_ALL_PACKAGES` was added to attribute traffic to apps. This is a Play-restricted permission; the policy declaration is tracked in `docs/backlog.html` (SB-061).

## 🔄 Update Notes

- Install over v0.1.0 through Settings → Check for updates, or sideload the universal APK. The signing certificate is unchanged, so the update installs in place.
- New runtime prompts appear when you first open Network: usage access (already requested during onboarding) and VPN consent when enabling the firewall. Notifications are needed for anomaly alerts.
- The firewall is off by default. When enabled with **Allow all**, it does nothing until you block at least one app; **Block unknown apps** pre-selects sideloaded apps.
- Open-port listing may be unavailable on Android 10+ because of `/proc/net` restrictions; the UI explains this.
