# v0.9.2 — TCP connect fix

The v0.9.1 `SecureBoxTunnel` log showed DNS working and TCP SYNs reaching the tunnel, but every outbound TCP connection failed **immediately**. The cause was `tcpNoDelay` being set before `Socket.connect()` — Android rejects that on an unconnected socket, so the forwarding engine never opened a single upstream TCP connection.

## Fix

- `tcpNoDelay` is now set **after** `connect()` succeeds.
- The captured exception is included in the `tcp connect failed` log so the next failure is diagnosable.

Everything else from v0.9.1 remains:

- IPv4-only tunnel
- explicit DNS-server route
- protected plaintext DNS fallback when DoH fails
- `SecureBoxTunnel` diagnostics
- combined firewall + DNS in one VPN

## Test

1. Install v0.9.2.
2. Enable **Local firewall** and **DNS Shield**.
3. Open a browser and try:
   - `https://1.1.1.1`
   - a normal HTTPS site
4. Check a blocked app.

Expected log lines now:

```text
tcp syn :443
tcp connected :443
```

If you still see `tcp connect failed`, the log now includes the exception (`protect failed`, `ENETUNREACH`, timeout, etc.). Send that line.

## Privacy

Unchanged from v0.9.0:

- allowed traffic is relayed on-device through protected sockets
- nothing is sent to a SecureBox server
- TLS is not intercepted
- blocked apps are reset/dropped
- the plaintext DNS fallback is used only when DoH fails
